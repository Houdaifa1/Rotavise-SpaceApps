# Step 05 — API and method review

Checked: 2026-09-27. Scope: revise calendars, sequences and constraints. This is
a focused primary-source review, not an exhaustive search of the internet.
**No new external API is called by the calculation engine.** Weather calculations,
water balance and ranking remain Step 06. Public sources do not establish that our
three research profiles have reviewed local executable durations or health rules.

## Decisions that affect this step

- Preserve the selected stack and the two-successive-cycle model. Many crop pairs
  can be compared; each pair contains two future crops.
- Execute only reviewed, applicable, explicitly scoped **hard** calendar/duration
  rules. A reference or soft duration cannot produce binding harvest dates.
- Tied latest historical harvest dates do not establish one immediate predecessor.
  Return uncertainty rather than selecting a crop by array order.
- Keep SHA-256 catalog identities unchanged while removing Node-specific hashing
  from the engine's dependency graph. Pin `@noble/hashes` **2.4.0**, MIT, no package
  dependencies, Node requirement >=20.19.0, actually installed under Node 24.19.0.
  Use documented `sha256(Uint8Array)`/hex conversion; no custom cryptography.
  [Maintainer documentation](https://github.com/paulmillr/noble-hashes).
- Record corrected behavior as `sequence-engine-2` / `sequence-policy-2`.
  No planner output is yet persisted by the intake API; no SQL migration is needed.

## Methods actually used

| Method                                  | Meaning / boundary                                                                                                                                                                                                                            |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Temporal.PlainDate` 0.5.1 / JSBI 4.3.2 | ISO calendar days without a timezone. Strict full dates; real leap days and recurring year-wrap windows. Harvest offset means elapsed calendar days. [Specification](https://tc39.es/proposal-temporal/docs/plaindate.html)                   |
| Complete two-cycle enumeration          | Union of executable planting windows; conservative duration envelope across executable rules. Second sowing must be after latest first harvest; last harvest within horizon. Every considered/unsupported choice retained.                    |
| Conservative evidence gating            | Region/system/cultivar/conditions/review must match; reference/research data cannot become hard dates/constraints. Unknowns remain conditions/gaps. Hard failures cannot be averaged into success.                                            |
| Typed constraints                       | Sourced pH method/range, explicit family prohibitions, calendar-year return intervals and verified issue/host/harvest-anchored calendar-day health breaks. Unknown dates and predecessor ambiguity remain visible.                            |
| Bounded exhaustive search               | ≤250000 examined combinations,≤5000 schedule records,≤2MiB serialized output. Limit failure returns no successful partial result. Result contract cross-checks search accounting.                                                             |
| Content identity / determinism          | Canonical UTF-8 JSON →SHA-256 via Noble. Independent native hash comparison and unchanged real release hash. Transitive import probe rejects Node builtins and removes Buffer; calculation runs with `Date.now` throwing and forbidden fetch. |

Temporal's full polyfill initializes unused `Now` clock internals at module load.
This is not a claim of a clock-free import. The test imports it under two different
controlled clock values, forbids clock reads during evaluation and compares full
results. Production code does not monkey-patch the clock or use `Temporal.Now`.
Calendar results depend on supplied assessment dates, not runtime time.

## Future method: water balance is not implemented

FAO56 reference evapotranspiration uses weather/radiation inputs and a defined
reference surface. Crop evapotranspiration additionally needs appropriate crop
coefficients/stages; irrigation adequacy also needs effective rainfall, soil/root
storage, losses, water delivery and efficiency. `rainfall − ET₀` or a demand class
alone cannot establish sufficient irrigation. Until a reviewed supported balance
and required inputs exist, return **irrigation adequacy unknown**.
[FAO56 equation](https://www.fao.org/4/x0490e/x0490e06.htm),
[required inputs/ET₀ calculation](https://www.fao.org/4/x0490e/x0490e08.htm).

## Reproduce the research

From repository root with Node 24.19.0:

```sh
node tooling/engine/research.mjs .artifacts/step-05-api-review-new
```

This performs nine small sequential public GETs and saves raw bodies/manifest.
It is outside CI and may return exit 1 for missing data or request failure. The
recorded SoilGrids response is intentionally classified `no_data`; errors/nulls
are never converted to zeros. Timings are individual observations, not a controlled
benchmark or an uptime claim. Earthdata/EPPO/CDS authenticated extraction, local
ground-truth comparison and commercial deployment are not performed.
