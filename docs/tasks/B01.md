# B01 — Engine speed: pass the 25-second limit on GitHub

**Needs:** — · **Board:** [BOARD.md](BOARD.md) · **How:** [WORKFLOW.md](WORKFLOW.md)

## Problem

The GitHub check of 14 Nov 2026 (run 43606297757) failed two speed tests
while every result was correct:

- `tests/unit/rotation.test.mjs`: "catalog 0.15.0 declared keeps the recorded
  result and speed bound": 25.10 s, limit 25 s.
- `tests/unit/rotation-research.test.mjs`: "pinned engine exposes coverage and
  per-strategy references within the unchanged 25-second speed bound":
  25.25 s, limit 25 s.

The default catalog grew from 24 to 246 crops; GitHub's shared runners are
slower than a laptop.

## Do

1. Profile both cases (`node --cpu-prof`) and find where the time goes.
2. Make the engine faster without changing any result: the recorded result
   hashes in those tests must stay identical (see DECISIONS "Engine speed"
   for the earlier byte-identical speed-up).
3. Only if no safe speed-up exists: change the limit, with measured numbers
   from GitHub runs and a DECISIONS entry. Never just raise it to pass.
