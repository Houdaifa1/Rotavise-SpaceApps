# B04 — Sentinel-2 10 m field greenness (Planetary Computer)

**Needs:** B02 · **Board:** [BOARD.md](BOARD.md) · **How:** [WORKFLOW.md](WORKFLOW.md)

## Why

The app's greenness (HLS) is 30 m and goes through AppEEARS, which can take
hours and needs an Earthdata account. Microsoft Planetary Computer (a Space
Apps Global Offer, public STAC API, no account) has Sentinel-2 L2A at 10 m;
on 14 Nov 2026 the newest scene over Tadla was from 13 Nov 2026.

## Do

1. A server module that, for an owned field, searches the STAC API
   (`https://planetarycomputer.microsoft.com/api/stac/v1`, collection
   `sentinel-2-l2a`) for scenes over the field outline, filters by cloud using
   the scene classification band, and computes NDVI statistics (mean, spread,
   valid pixel share) per date inside the outline.
2. Store results with their source scene ids, dates and processing version, in
   the same owner-scoped way as the other observations (migration if needed).
3. Expose it through a contract in `packages/contracts` and OpenAPI; keep NASA
   HLS as the primary NASA record and label Sentinel-2 as ESA data.
4. Check Planetary Computer's terms and the Sentinel data licence; add them to
   `THIRD_PARTY_NOTICES.md` and `docs/REFERENCES.md`.

## May change

A new server module, contracts, a migration, tests, docs. Not `apps/web`
(that is F12).

## Checks

`pnpm lint`, `pnpm typecheck`, `pnpm test:unit`, `pnpm test:integration`.

## Done when

For a real field in Tadla the API returns a 10 m greenness series with scene
dates and cloud filtering, and all checks pass.
